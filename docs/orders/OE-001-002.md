## Estado

A homologação foi fechada após correção dos erros que impediam a importação/build no Vercel, execução positiva do gate `npm run check` no deployment ligado ao GitHub e comprovação separada das regras de persistência/concorrência no Neon de homologação. A OE-001-003 está liberada para implementação, mas ainda não foi implementada.

## Escopo implementado

### Frontend
- Página pública passou a consumir uma única configuração revisionada.
- Marca fixa HortiVitalMix preservada.
- Título do documento, idioma da página, cor de tema, slogan, localização e contatos usam a mesma versão de configuração.
- Header, footer e conteúdo público foram ligados ao contrato canônico.
- Criada a tela `/admin/configuracao` com:
  - identidade editável apenas nos campos permitidos;
  - contatos públicos opcionais;
  - região;
  - localidade, moeda e fuso horário;
  - revisão atual;
  - estados de persistência indisponível, sucesso, conflito, acesso negado e erro;
  - ação de recuperação/recarregamento.
- Layout responsivo para desktop, tablet e mobile, mantendo a identidade verde/laranja/branco das referências visuais.
- A interface nunca confirma uma gravação antes da resposta válida do backend.

### Backend
- Criado contrato runtime com Zod para configuração pública e comando administrativo.
- `GET /api/v1/config` permanece público.
- `PATCH /api/v1/admin/configuration` exige a permissão server-side `platform.configuration.manage`.
- Sem identidade/autenticação real ligada ao resolver, o PATCH responde 403; não existe bypass de desenvolvimento ou administrador simulado no caminho de produção.
- `expectedRevision` implementado para concorrência otimista.
- `commandId` + hash canônico implementados para idempotência.
- Reutilização do mesmo `commandId` com payload diferente retorna conflito.
- Validação inválida retorna 422 antes de persistir.
- Falha de persistência retorna indisponibilidade, sem simular sucesso.
- Erros padronizados continuam correlacionados por `requestId`.

### Correções que removeram o erro de importação/build
Durante a homologação foram encontrados e corrigidos dois erros reais de TypeScript:
1. `UnavailablePage` utilizava `<BrandLogo />` enquanto a prop `brand` era obrigatória. O componente passou a aceitar fallback canônico seguro da marca.
2. `foundationService.ts` importava `AppEnvironment` de `server/config/runtime.ts`, que não exportava esse tipo. O import foi corrigido para o domínio compartilhado canônico.

Também foram endurecidos:
- `vercel.json` com framework Vite, install/build/output explícitos e rewrite SPA compatível;
- `package.json` com `engines.node = 22.x`;
- CI para não depender de `npm ci` sem lockfile.

## Diagnóstico do gate executável
A tentativa de homologar o artefato pelo conector Vercel foi repetida também com um projeto mínimo que não dependia do código HortiVitalMix. O conector retornou inicialmente `INITIALIZING` e um deployment id, mas imediatamente depois `get_deployment` e `get_deployment_build_logs` retornaram `Deployment not found`. Isso demonstra que a ausência de evidência de build pelo Vercel MCP não é suficiente para atribuir falha ao código desta OE.
